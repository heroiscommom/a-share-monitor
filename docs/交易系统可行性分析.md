# 个人量化交易系统可行性分析

> 2026-08-26 · 基于 a-share-monitor 现状的演进规划
> 目标：从「盯盘 + 信号 + 看板」升级为「信号 → 风控 → 建议 → 复盘」闭环的个人交易系统

---

## 一、现状盘点：已经有什么（基础远超多数个人项目）

| 层 | 已有能力 | 状态 |
|----|---------|------|
| 数据层 | 腾讯实时行情/日K/分时、新浪资金流、东财涨停池、申万板块、baostock 备用 | ✅ 全免费 |
| 信号层 | 超跌均值回归 6 因子 + 动量 6 因子 + 市场状态门控（回测验证） | ✅ 有验证 |
| 择时层 | 支撑压力 v2（密度剖面+守住率+风险评分）+ 断板低吸 + 龙头梯队 | ✅ 已落地 |
| 情绪层 | 涨停家数温度计（冰点/回暖/活跃/高潮 + 趋势） | ✅ 已落地 |
| 回测层 | 因子有效性回测 + 组合级回测（Top20/行业中性化/市场状态分层）+ walk-forward | ✅ 严谨 |
| 推送层 | Server酱微信（S/A 实时）+ QQ邮箱日报（收盘）+ 自动报告（15:35） | ✅ 已落地 |
| 部署层 | GitHub Actions 定时（5分钟/收盘/周回测）+ Pages 看板，零成本 | ✅ 已落地 |
| 决策层 | 持仓建议模块（止损/止盈/低吸/减仓规则 + 整体仓位） | ✅ 刚落地 |

**结论：信号与基础设施已是"准交易系统"，缺的是风控纪律化、执行记录、复盘闭环。**

## 二、完整交易系统的构成（对照差距）

```
┌────────────────────────────────────────────────────┐
│ 个人量化交易系统                                     │
│                                                    │
│  ① 信号层(已有)  ② 风控层(部分)  ③ 执行层(缺)       │
│  ④ 记录层(缺)    ⑤ 复盘层(缺)    ⑥ 优化层(已有)     │
└────────────────────────────────────────────────────┘
```

| 环节 | 现有 | 缺口 |
|------|------|------|
| ① 信号生成 | ✅ 多策略信号 | — |
| ② 风险控制 | ⚠️ 规则化建议（止损/仓位），但**未强制** | 单票止损线、最大回撤熔断、仓位上限 |
| ③ 交易执行 | ❌ 手动（建议邮件/微信 → 自己下单） | 这是**唯一不可自动化**的部分（合规+实盘API门槛） |
| ④ 交易记录 | ❌ 无 | 每笔买卖需录入（代码/价格/数量/时间/原因） |
| ⑤ 复盘分析 | ❌ 无 | 交易 vs 信号一致性、胜率归因、错误类型统计 |
| ⑥ 策略迭代 | ✅ 回测框架 | — |

## 三、关键设计决策

### 3.1 执行方式：手动执行 + 系统监督（推荐，合规安全）
- **不建议接实盘 API**（券商接口门槛、合规风险、滑点不可控）
- 系统只做：给建议（邮件/微信）→ 你手动下单 → 录入成交 → 系统自动复盘
- 好处：符合"辅助决策"定位，无法律灰色地带，且数据积累后仍可迁移到自动执行

### 3.2 风控纪律（系统强制，不靠自律）
- **单票止损线**：浮亏 -8% 且破支撑 → 建议止损（已有规则，需加上"连续 N 日未触发则人工确认"）
- **仓位上限**：单票 ≤ 20% 总资金；持仓总市值 ≤ 70%（震荡市）/ ≤ 80%（上涨市）
- **情绪熔断**：情绪冰点（涨停<30）时信号降级（S→A，A→B），高潮（>80）时禁止追高
- **回撤熔断**：账户回撤 >10% → 强制降仓至 50% 以下，回测确认后再恢复

### 3.3 策略组合（多策略分散，避免单策略失效）
| 策略 | 适用市场 | 仓位配比建议 | 依据 |
|------|---------|-------------|------|
| 超跌反弹（均值回归） | 下跌/震荡市 | 40% | 回测胜率 56%+，下跌市最强 |
| 断板低吸（龙头） | 情绪回暖期 | 30% | 回测胜率 66.7%（样本小） |
| 动量强势 | 上涨市 | 30% | 上涨市唯一有效 |

### 3.4 数据闭环（交易记录 → 复盘 → 策略优化）
```
建议 → 执行 → 成交记录(portfolio_trades.json)
                      ↓
每周复盘: 建议正确率 / 未执行原因 / 盈亏归因
                      ↓
修正规则参数 → 回测验证 → 新建议
```

## 四、分阶段路线图

| 阶段 | 内容 | 交付 | 工作量 |
|------|------|------|--------|
| **P1（已完成）** | 自动报告邮件（回测+持仓建议+情绪龙头） | auto_report.py + workflow | ✅ |
| **P2** | 交易记录模块：手动录入成交（网页表单/Issue 命令），落盘 trades.json | 交易流水 + 持仓成本自动更新 | 小 |
| **P3** | 周复盘报告：本周建议 vs 实际执行对比、胜率/盈亏归因、错误统计 | 每周日邮件 | 中 |
| **P4** | 风控强制化：情绪熔断/回撤熔断/仓位上限进规则引擎，建议分级带"强制"标记 | 风控规则引擎 | 中 |
| **P5** | 资金曲线看板：账户净值曲线 + 基准对比 + 回撤标注（前端 ECharts） | 净值看板 | 中 |
| **P6** | 参数自适应：每季度用新数据重跑回测，自动更新阈值（已有框架，加定时） | 季度调参报告 | 小 |

## 五、风险与边界（必须清楚）

1. **回测≠实盘**：幸存者偏差、滑点低估、情绪冲击——现有回测已部分处理（非重叠/成本/一字板剔除），但打板类策略滑点仍被低估
2. **样本量约束**：断板低吸 18 个样本、龙头策略小样本——结论只作方向，仓位要轻
3. **合规**：仅供个人研究；系统给"建议"不给"指令"，不代客理财，不构成投顾
4. **数据源稳定性**：腾讯/东财/新浪免费接口可能变更或限流——多源冗余已做（baostock 备用），需监控
5. **情绪化执行**：系统最大的敌人是"不执行"——P2 的交易记录 + P3 的复盘就是为此设计
6. **单策略失效**：均值回归在上涨市失效（已实测 46.4%）——所以必须多策略 + 市场状态门控

## 六、结论

**可行，且当前项目已具备 70% 基础。** 真正的增量是 P2（交易记录）和 P3（复盘闭环）——把"建议"变成"可追溯的决策过程"。建议按 P2 → P3 → P4 顺序推进，每个阶段都能独立产出价值：

- P2 落地后：你开始积累自己的交易数据（这是个人交易系统最贵的资产）
- P3 落地后：系统开始"教"你复盘，纠正行为偏差
- P4 落地后：风控纪律化，避免大亏

> 一句话：**你不是缺策略，是缺记录和纪律。交易系统的核心价值 = 把建议变成纪律，把纪律变成数据，把数据变成更好的建议。**
