## 一、舆论扫描作为选股条件：可行 ✅（但分两个层次）

### 1.1 数据源可行性（全部免费、无需 token）

| 数据源 | 内容 | 频率 | 可用性 | 稳定性 |
|--------|------|------|--------|--------|
| 东方财富**人气榜**（akshare `stock_hot_rank_em`） | 全市场个股热度排名 | 分钟级 | 高 | 中（东财反爬需控制频率） |
| 东方财富**股吧评论**（`stock_comment_em`） | 个股最新/热门评论 | 分钟级 | 高 | 中 |
| 东财**个股新闻**（`stock_news_em`） | 个股新闻标题 | 分钟级 | 高 | 高 |
| 东财**研报**（`stock_research_report_em`） | 机构研报（评级/目标价） | 日级 | 高 | 高 |
| 深交所**互动易**（`stock_irm_cninfo`） | 投资者问答 | 日级 | 高 | 高 |
| **龙虎榜**（`stock_lhb_detail_em`） | 机构/游资席位 | 日级 | 高 | 高 |
| 央视**新闻联播**文字稿（`news_cctv`） | 政策面 | 日级 | 中 | 高 |

### 1.3 情绪因子怎么构建（两个层次，成本差 5 倍）

**A. 热度因子（推荐先做，成本低、噪声小）**
- 指标：人气榜排名、股吧日讨论量、讨论量变化率（环比增速）
- 逻辑：热度骤升 = 资金关注 = 短线机会（配合资金流验证）
- 实现：一个函数拉数据 + 归一化打分，**不需要 NLP**

**B. 情感因子（成本高、需验证）**
- 指标：评论/新闻的正负面情感得分（-1~+1）
- 实现：中文情感分析（snownlp 轻量 / 大模型 API 打分）
- 风险：股吧噪声极大（水军、反话、谐音），**必须做 IC 回测验证**，无效就不上
- 学术上有效（EMM 论文），但工程落地质量差异大

### 1.4 风险
- 东财接口有反爬，需限频 + 缓存（我们现有 30 分钟缓存机制可复用）
- 热度因子在**散户主导的小票**上更有效，大盘股意义小
- 舆情数据是"锦上添花"，不能独立成策略，必须与价格/资金因子组合

## 二、多策略量化选股：可行 ✅（本质是"打分函数 + 筛选规则 + 回测验证"）

### 2.1 建议策略清单（按实现成本排序）

| # | 策略 | 数据需求 | 现有基础 | 成本 | 回测预期 |
|---|------|----------|----------|------|----------|
| 1 | 超跌反弹（均值回归） | 日K | ✅ 已上线 | 0 | 已验证（下跌市最强） |
| 2 | 强势动量 | 日K | ✅ 已上线 | 0 | 已验证（上涨市有效） |
| 3 | 主力资金流 | 资金流 | ✅ 已有数据 | 低 | 资金流入+超跌共振 |
| 4 | 技术形态（放量突破/均线多头） | 日K | ✅ 数据够 | 低 | 需回测 |
| 5 | 低估值（PE/PB/股息） | 基本面 | ✅ 行情自带 | 低 | 防御型，慢 |
| 6 | 舆情热度 | 人气榜/股吧 | ❌ 需接入 | 中 | 短线，需验证 |
| 7 | 板块轮动（行业相对强度） | 板块 | ✅ 已有 | 中 | 中长线 |
| 8 | 北向资金（外资动向） | 北向 | ❌ 需接入 | 中 | 大盘风向标 |

**核心结论**：1、2 已验证；3-5 用现有数据一周内可加；6-8 需要新数据源（akshare 一次接入全部搞定）。

### 2.2 架构设计（复用现有框架）

```
数据层（新增 akshare 采集，每日/每5分钟）
  ├ 行情/日K（已有腾讯）
  ├ 资金流（已有新浪）
  ├ 人气榜/股吧/新闻/研报/北向（新增，akshare）
因子层（新增 strategies.py：每个策略一个打分函数，0-100）
  ├ mean_reversion(已有) / momentum(已有)
  ├ moneyflow / breakout / value / sentiment / sector_rotation
策略层（候选池 + 组合器）
  ├ 单策略 TopN 列表
  ├ 多因子加权（IC 加权）组合
  ├ 市场状态门控（已有，按状态切换策略）
表现层（页面）
  ├ 候选股区块：策略按钮组（超跌/动量/资金/技术/估值/舆情）
  ├ 点击按钮 → 切换该策略的 Top10 候选（附评分和理由）
  └ 回测对比表（每个策略的胜率/收益/回撤）
```

## 三、页面按钮交互：可行 ✅ 且适合零后端架构

### 3.1 方案（推荐：纯静态预计算）
- 每天收盘后 Actions 跑 `strategies.py`，**把每个策略的 Top10 结果分别存成 JSON**（`data/strategies/{策略名}.json`）
- 前端在"候选股"区放一排按钮（超跌｜动量｜资金流｜技术形态｜低估值｜舆情热度）
- **点击按钮 = 切换加载对应的 JSON**，纯前端切换，零后端、零服务器
- 和我们现有架构（数据预计算 + Pages 静态展示）完全一致

### 3.2 交互细节
- 默认展示"市场状态组合"（D策略，当前最优）
- 每个策略卡片显示：策略说明 + 当日 Top10（代码/名称/评分/现价/支撑/入选理由）
- 回测对比区块显示各策略的历史表现（胜率/Sharpe/回撤），帮用户判断该信谁

## 四、落地路线图（3 阶段）

**Phase 1（1-2 天，低成本高确定性）**
- 策略框架 `strategies.py`：把现有超跌/动量 + 新增 资金流/技术形态/低估值 共 5 个策略统一
- 页面按钮组 + 策略 JSON 切换
- 每个策略做组合级回测（复用 portfolio_backtest.py 框架）出对比表

**Phase 2（2-3 天，中成本）**
- 接入 akshare：人气榜 + 股吧讨论量 + 新闻（**先只做热度因子，不做情感**）
- 舆情热度策略 + 回测验证（热度因子独立 IC 检验）
- 北向资金接入（可并入资金流策略）

**Phase 3（按需，高成本不确定）**
- 情感分析（snownlp/大模型打分）+ IC 验证
- 有效才并入；无效就砍掉——**用数据说话**

## 五、结论

| 需求 | 可行性 | 关键前提 |
|------|--------|----------|
| 扫描市场舆论 | ✅ 可行 | 热度因子直接可用；情感因子需 NLP+验证 |
| 舆论作为选股条件 | ✅ 可行 | 必须与其他因子组合，独立使用风险大 |
| 多策略选股 | ✅ 可行 | 1-5 低成本，6-8 需接入 akshare |
| 页面按钮切换策略 | ✅ 可行 | 纯静态预计算 JSON，符合现有架构 |

**总成本估算**：Phase 1 + 2 约 4-5 天工作量，全部免费数据源。
**最大不确定性**：舆情情感分析的准确率（需 IC 验证后才算数）；东财反爬稳定性（限频+缓存可缓解）。
