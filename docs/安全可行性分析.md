# 个人量化交易系统安全可行性分析

> 覆盖：凭据管理 / 权限边界 / 数据隐私 / 注入与误操作 / 供应链 / 合规

## 一、架构总览（先看风险面在哪）

```
GitHub Pages(公开)                GitHub Actions(自动)              你的邮箱/微信
┌──────────────┐  读 data/*.json  ┌──────────────────┐   SMTP    ┌──────────┐
│ 前端看板      │◄─────────────── │ 定时任务/命令处理  │──────────►│ 报告/提醒 │
│ 交易录入表单   │  Issue 提交      │ monitor/digest/   │   Server酱 │          │
└──────────────┘ ───────────────► │ trade/weekly     │           └──────────┘
     手机/浏览器                   └──────────────────┘
          │                                │
          │  push 代码/数据                 │ commit data/
          ▼                                ▼
       公开仓库 = 代码 + 行情数据 + 【持仓/交易流水】← 主要隐私风险点
```

**核心结论先行：系统安全可行，但有一个必须正视的隐私风险——持仓与交易数据存放在公开 GitHub 仓库中。**

## 二、逐项安全分析

### 2.1 凭据安全 ✅（已达标）

| 凭据 | 存放 | 状态 |
|------|------|------|
| QQ 邮箱 SMTP 授权码 | GitHub Secrets（不可读、仅 Actions 注入） | ✅ |
| Server酱 SendKey | GitHub Secrets | ✅ |
| 本地 .env | 已 gitignore，不入库 | ✅ |
| 前端 | **零凭据**（纯静态，无 token/API key） | ✅ |

- Secrets 只有 Actions 运行时可见，仓库公开也不泄露
- 前端不调用任何需认证的 API，不存在抓 token 的面

### 2.2 权限边界 ✅（最小化）

- 各 workflow 声明 `permissions: contents: write / issues: write`，**未使用高权限 token**
- Issue 机器人用 `github.token`（临时、限仓库），不开通 Personal Access Token
- ⚠️ 注意：`contents: write` 意味着任何能触发 workflow 的人都能间接提交——但 Issue 触发有命令格式白名单（见 2.4），且 `issues: write` 仅评论/关闭

### 2.3 数据隐私 ⚠️（唯一重大风险）

**风险**：免费 GitHub Pages 要求**公开仓库**。当前 `data/trades.json`（持仓/成本/盈亏）和 `data/equity_history.json`（净值）都在仓库中 → **任何访问你 Pages 的人都能看到你的持仓和盈亏**。

| 影响 | 说明 |
|------|------|
| 隐私泄露 | 持仓、成本、盈亏暴露给公众 |
| 被针对 | 小资金影响小，但心理不适；大资金可能被围观/跟单 |

**缓解方案（按推荐排序）**：

1. **数据脱敏落库**（推荐，改动小）：`data/trades.json` 只存代码+股数+价格，**名称/备注模糊化**；前端显示时再本地映射名称。成本信息仍可推导，属"半脱敏"
2. **私有仓库 + 免费静态托管替代**（彻底）：
   - 代码与数据放**私有仓库**（Actions 照常跑）
   - Pages 改用 **Cloudflare Pages / Vercel / Netlify**（免费、可私有源）——README FAQ 已提过此方案
   - 代价：需要一次迁移（~30 分钟），且这些平台对国内访问速度一般
3. **加密存储**（复杂）：trades.json 用对称加密，前端加载时用口令解密——但口令必须由你手动输入，手机体验差，不推荐
4. **接受风险**：如果你持仓规模小、不介意公开，维持现状亦可（很多量化博主公开实盘）

**我的建议**：先做方案 1（脱敏）+ 明确告知你风险，若在意隐私再迁移方案 2。

### 2.4 注入与命令安全 ⚠️（已基本防护）

Issue 机器人解析 `/trade` 命令：

- ✅ 正则白名单：`buy|sell|pnl` + 6位数字代码 + 数字金额 → **无法注入 shell 命令**（参数不拼 shell，直接传 Python 函数）
- ✅ 数字校验：股数/价格必须为数字，非数字直接拒绝
- ⚠️ 未校验：代码合法性（任意 6 位数字都能录入，包括不存在的股票）——建议后续加"查询腾讯接口确认代码存在"
- ⚠️ 未做幂等：重复提交同一 Issue 不会重复处理（Issue 只处理一次 opened），但**同内容开两个 Issue 会录两次**——靠"关闭 Issue"提示人工核对

### 2.5 操作安全 ✅（有回退）

- `trade.py undo` 撤销最后一条（已实现）
- 所有交易流水有 id + 时间戳，可审计
- 持仓推导是纯函数，从流水重算，不会因误操作丢失

### 2.6 供应链 ✅（需一次加固）

- 当前 Actions 用 `actions/checkout@v4`、`setup-python@v5`（大版本锁，会跟随 minor 更新）
- 建议锁 commit SHA（如 `@a5f4a1e...`）防供应链投毒——对个人项目风险极低，可选做

### 2.7 合规 ✅（定位清晰）

- 系统只出**建议**，不代下单、不代客理财、不构成投顾
- 免责声明已内置在报告/README/页面
- 数据来自免费公开接口，无版权风险

## 三、风险评级总表

| 风险 | 等级 | 现状 | 建议动作 |
|------|------|------|---------|
| 持仓数据公开泄露 | 🔴 高 | 存在 | 脱敏或迁私有源托管 |
| Issue 命令注入 | 🟡 中 | 已防 shell 注入 | 加代码存在性校验 |
| 重复录入 | 🟡 中 | 人工核对 | 加同代码同日去重提醒 |
| Secrets 泄露 | 🟢 低 | 已达标 | 定期轮换授权码 |
| 供应链投毒 | 🟢 低 | 大版本锁 | 可选锁 SHA |
| 前端 XSS | 🟢 低 | 数据自产自销 | 渲染时用 textContent 或转义 |

## 四、结论

**系统在「凭据、权限、操作、合规」维度安全达标；唯一高风险项是「公开仓库暴露持仓隐私」。**

安全加固建议按优先级：
1. **P0：决定持仓数据是否公开**——脱敏 or 迁 Cloudflare Pages（私有源）
2. **P1：trade 命令加代码存在性校验**（腾讯接口确认），防手误录入无效代码
3. **P2：重复录入提示**（同代码同日相同方向/股数/价格时在 Issue 回复中警告）
4. **P3：定期轮换 SMTP 授权码 + Server酱 Key**

> 一句话：系统本身是安全的，风险在你「公开了你的钱包」。选脱敏（10分钟）还是迁移（30分钟），取决于你对持仓隐私的在意程度。
